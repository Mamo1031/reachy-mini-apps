# experiment — Reachy Mini 実験コントローラ(開発者向け)

実験を行う人向けの使い方・工夫点は [ルートの README](../README.md) を参照。ここは構成・仕組み・テストのメモ。

幼児(3〜4 歳)向け「共感的 vs 論理的な励まし」実験で、実験者がブラウザのボタンを押すと
Reachy Mini が対応する「発話 + 動作」を即座に再生する操作ツール。

- 台本: イントロ A(順序条件で A1,A2,A3,A4,A5 / A1,A2,A6)、共感 B1〜B10、論理 C1〜C10、相づち(うん / ちがうよ / そうだね / できたね)
- ストップ(発話と動作を即中断)/ 一時停止(顔追跡とアイドル動作を止めて静止)
- 接続監視(緑 / 赤ランプ)と自動復旧、セッションログ(CSV + JSON)
- ロボット名・実験者名・台本の文言・ジェスチャー割当・お手本の位置・声・タイマーなどは**すべて設定画面から変更可能**

## 必要なもの

- macOS(Apple Silicon)、[uv](https://docs.astral.sh/uv/)、Homebrew(7-Zip の導入に使う)
- Reachy Mini(無線版)。Mac と**有線 LAN**で同じネットワークに接続(実験中の切断を避けるため)
- 操作端末: Mac のブラウザ、または同じネットワークの iPad(横向き推奨)

## セットアップ(初回のみ)

```bash
cd experiment
./setup_voicevox.sh      # VOICEVOX エンジン(約 1.8 GB)を tools/voicevox/ に導入
uv sync --all-groups     # Python 依存
```

## 起動

```bash
cd experiment
./run.sh                 # http://localhost:8080 (iPad からは http://<MacのIP>:8080)
```

サーバーが VOICEVOX エンジンを自動起動し、ロボットに接続して音声を準備する(開始画面にチェックリストが出る)。
ロボットの電源が入っていなくてもサーバーは起動し、接続できるまで待つ。

### 実験の流れ

1. **開始画面**: 子どもの名前(ひらがな)、ちゃん / くん、順序条件、励まし条件を入れて「準備してはじめる」。名前入りの音声(A2)がここで合成される。
2. **操作画面**: イントロのボタンを順に押す → 「本番開始」で 8 分タイマー → 励ましボタン(約 30 秒ごとの目安表示あり)→ 「セッション終了」。
3. ログは `logs/<日時>_<名前>.csv`(押したボタン・時刻・結果)と同名の `.json`(条件・設定のスナップショット)。

### 設定画面

一般(名前・ロボット URL・タイマー)/ 位置(お手本・写真カード・ピースの方向。「テスト」で実機確認)/
声(VOICEVOX の話者・速度・高さ・抑揚、試聴、名前の読み辞書)/ 台本(文言とジェスチャー割当、「ロボットで再生」)/
動作(顔追跡・頭揺れ・アイドル・可動域・音声と動作のずれ補正・音量)。
保存すると即反映される(文言を変えた音声は次に押したときに自動で合成し直す)。

## 仕組み(要点)

- ロボット内デーモンの REST API(`http://reachy-mini.local:8000`)を直接使う。SDK は使わない。
- 動作は Mac 側で軌道を生成し、デーモンの WebSocket(`/ws/sdk` の `set_full_target`)へ 30 Hz(設定可)で流す。応答を待たないので Wi-Fi の往復遅延に縛られない。WebSocket が使えないときは HTTP の `set_target` に自動で落ちる。公式の感情モーション集(`moves/`、Apache-2.0)とパラメトリックなキーフレーム(`gestures.json`)を同じ仕組みで再生する。
- デーモン(v1.10.0)は HTTP keep-alive の接続再利用に応答しない癖があるため、HTTP は毎回新しい接続を張る(`Connection: close`)。名前解決(`reachy-mini.local`)は一度だけ行い IP をキャッシュする。
- 実機の頭部機構には 2〜3° の遊びがあり、指令に対して読み取り値は少し小さく出る(振幅 8° → 6° 程度)。ジェスチャーの見た目には影響しない。
- 顔追跡はデーモン内蔵の機能を使う(映像は Mac に送られず、保存もしない)。頭を動かすジェスチャーの間だけ追跡を一時停止し、終わると戻す。
- 音声は VOICEVOX でローカル合成し、ロボットへアップロードして本体スピーカーで鳴らす。合成結果は `cache/` にキャッシュ。
- 1 秒ごとにデーモンの状態を確認し、切断→復帰時はモーター有効化 → ニュートラル姿勢 → 音声の再アップロード → 追跡設定の再適用を自動で行う。

## トラブルシュート

| 症状 | 対処 |
|---|---|
| 「ロボット接続待ち」が続く | ロボットの電源・LAN ケーブルを確認。`reachy-mini.local` が引けない場合は設定 > 一般 > ロボット URL に IP(例 `http://192.168.1.83:8000`)を入れる |
| 「VOICEVOX エンジンが見つかりません」 | `./setup_voicevox.sh` を実行。ログは `cache/voicevox.log` |
| ダッシュボード(Reachy Mini Control)のアプリが動いている | 先に停止する(ロボットの取り合いになる) |
| 音声と動作のタイミングがずれる | 設定 > 動作 > 音声先行(ms)を調整 |
| 頭が動かない(アンテナだけ動く) | 顔追跡が有効のまま外部から goto された場合に起きる。操作画面の「ストップ」で復帰する |
| 動きがカクつく・遅れる | Wi-Fi 同士だと往復遅延が揺れる。Mac とロボットを有線 LAN にする。設定 > 動作 > 送信レートを下げるのも有効 |
| ロボットを休ませたあと | 操作画面の「起こす」を押すと無音でニュートラルに戻る |

## テスト

```bash
cd experiment
uv run --all-groups pytest -q      # ロボット不要(偽デーモンで検証)
```

## クレジット

- 音声合成: [VOICEVOX](https://voicevox.hiroshiba.jp/)。使用キャラクターのクレジット表記(例: `VOICEVOX:ずんだもん`)が必要。各キャラクターの利用規約に従うこと。
- モーション: Pollen Robotics [reachy-mini-emotions-library](https://huggingface.co/datasets/pollen-robotics/reachy-mini-emotions-library)(Apache-2.0)。詳細は `moves/CREDITS.md`。
