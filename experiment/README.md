# experiment — Reachy Mini 実験コントローラ(開発者向け)

実験を行う人向けの使い方・工夫点は [ルートの README](../README.md) を参照。ここは構成・仕組み・テストのメモ。

幼児(3〜4 歳)向け「共感的 vs 論理的な励まし」実験で、実験者がブラウザのボタンを押すと
Reachy Mini が対応する「発話 + 動作」を即座に再生する操作ツール。

- 台本: イントロ A1〜A5-2(常にロボット先行。順序条件は 2026-09-29 に廃止し、`order` は記録の互換のため `robot_first` 固定)、共感 B1〜B10、論理 C1〜C10、相づち BC1〜BC5(「私は手伝えないから、自分で頑張ってみよう」を含む)
- 声は**録音した肉声**か VOICEVOX の合成を選べる(`settings.json` の `tts.source`)
- ストップ(発話と動作を即中断)/ 一時停止(顔追跡とアイドル動作を止めて静止)
- 顔追跡は**アプリ側**で首と腰を動かす方式(デーモン内蔵の首だけの追跡にも切り替え可)
- 接続監視(緑 / 黄 / 赤ランプ)と自動復旧、サーバー再起動後のセッション復元、電池の予兆(稼働時間・低電圧)
- セッションログ(CSV + JSON)
- ロボット名・実験者名・台本の文言・ジェスチャー割当・お手本の位置・声・動きの速さ・タイマーなどは**すべて設定画面から変更可能**

## 必要なもの

- macOS(Apple Silicon)、[uv](https://docs.astral.sh/uv/)、Homebrew(7-Zip の導入に使う)
- Reachy Mini(無線版)と **USB-C 有線 LAN アダプタ 2 個**(Mac 側とロボット側)。無線版に LAN 端子は無い
  - Mac 側は macOS が標準で認識するチップを使う(Realtek RTL8153 / ASIX AX88179B。旧 AX88179 は macOS 15 では動かない)
  - Mac とロボットを直結し、固定 IP(Mac `192.168.100.1/24`、ロボット `192.168.100.2/24`、ロボット側は NetworkManager の `wired-static`)。手順は[ルートの README](../README.md) の 2-2
  - `settings.json` の `robot.base_url` は `http://192.168.100.2:8000`(コード側の既定値だけが `reachy-mini.local`)
- 操作端末: Mac のブラウザ、または**同じ Wi-Fi にいる** iPad(横向き推奨)。ロボットの制御に Wi-Fi は使わない
- 電池の予兆を出す場合は Mac の ssh 鍵をロボットに登録(`~/.ssh/reachy_mini_ed25519`)

## セットアップ(初回のみ)

```bash
cd experiment
./setup_voicevox.sh      # VOICEVOX エンジン(約 1.8 GB)。合成の声を使うときだけ必要
uv sync --all-groups     # Python 依存
```

`tts.source = "recorded"` かつ `tts.recorded.fallback = "silent"` なら VOICEVOX は起動しない
(`needs_tts()`)。準備チェックの「VOICEVOX」は「録音の声を使うため起動しません」で ✓ になる。

## 起動

```bash
cd experiment
./run.sh                 # http://localhost:8080 (iPad からは http://<MacのWi-FiのIP>:8080)
```

### 実験者に配る

```bash
cd experiment
./tools/make_release.sh        # dist/実験コントローラ-<日付>.zip ができる(約 1.4 MB)
```

ルートの `はじめる.command`(ダブルクリックで起動)を同梱する。`uv` の導入 → `uv sync` → サーバー起動 →
ブラウザを開く、までを自動で行うので git もターミナルの知識も要らない。zip は `ditto` で作るので
実行権限が保たれる。VOICEVOX(2 GB)・テスト・キャッシュ・ログ・git は入れない。録音は入れる
(`.gitignore` されているので zip が唯一の配布経路)。

受け取る人に伝えること: 展開 → 「はじめる」をダブルクリック → 初回だけ Gatekeeper の許可(macOS 15: システム設定 > プライバシーとセキュリティ > 「このまま開く」/ macOS 14 以前: 右クリック → 開く)。手順は zip 同梱の `はじめに読んでください.txt`。署名・公証していない `.command` なので、ダウンロード経由(quarantine 属性付き)では必ず一度は止められる。

サーバーが VOICEVOX エンジンを自動起動し、ロボットに接続して音声を準備する(開始画面にチェックリストが出る)。
ロボットの電源が入っていなくてもサーバーは起動し、接続できるまで待つ。

### 実験の流れ

1. **開始画面**: 子どもの名前(ひらがな)、ちゃん / くん、励まし条件を入れて「準備してはじめる」。名前入りの音声(A2)はここで用意される(録音なら `names/<なまえ+呼び方>` を探し、無ければ無音)。
2. **操作画面**: イントロのボタンを順に押す → 「本番開始」で 8 分タイマー → 励ましボタン(約 30 秒ごとの目安表示あり)→ 「セッション終了」。
3. ログは `logs/<日時>_<なまえ+呼び方>.csv` と同名の `.json`(開始時点の条件・設定・台本の写し。再開しても書き直さない)。
   CSV は 9 列固定(`time_iso, elapsed_s, phase, kind, item_id, text, gesture, result, detail`)で、ボタン操作のほかに接続の変化・復旧・電圧低下・フェーズ・中断と再開・エラーも `kind` で区別して入る。
   同じフォルダの `.current_session.json` は再開用(正常終了で消える)。

### 設定画面

一般(名前・ロボット URL・タイマー・電池の予兆)/ 位置(お手本・写真カード・ピースの方向。「テスト」は**保存済みの値**で動く)/
声(声の種類(録音 / 合成)・録音の有無の一覧・VOICEVOX の話者・速度・高さ・抑揚・声の張り、試聴、名前の読み辞書)/
台本(文言とジェスチャー割当、「ロボットで再生」)/
動作(顔追跡の方式と速さ・頭揺れ・アイドル・ゆっくりさ(時間の倍率)と動きの大きさ・可動域(腰を含む)・音声と動作のずれ補正・音量)。
保存すると即反映される。声・名前・台詞の文言を変えると、その場で台詞ぶんの音声を裏で作り直す。
ロボットが未接続のときは作り直しが走らず、その台詞を押したときに作られる。

### 音声(録音 / 合成)

- `settings.json` の `tts.source` が `recorded` なら `recordings/<声>/<台詞 ID>.<拡張子>` を探して使う。名前入りの台詞(`{child}` を含むもの)だけは `recordings/<声>/names/<なまえ+呼び方>.<拡張子>`。
- 録音が無い台詞は `tts.recorded.fallback` に従う。`silent`(既定)なら**無音**で動作だけ再生し、CSV に「録音なし・無音」を残す。`voicevox` なら合成で代用する。
- m4a などの非 WAV は afconvert(無ければ ffmpeg)で 24 kHz モノラルの PCM にする(WAV はそのまま読み、複数チャンネルならモノラルに混ぜるだけ)。そのあと 20 ms 窓の実効値で前後の無音を詰め、`tts.params.loudness_db` が 0 より大きければ音量そろえをかけて `cache/` に置く。キャッシュキーは録音ファイルの絶対パス・サイズ・更新時刻・整形条件なので、録り直すと自動で作り直される。
- 追加した録音はサーバーを再起動しなくても次の準備で拾う。

## 仕組み(要点)

- ロボット内デーモンの REST API を直接使う(SDK は使わない)。接続先は `settings.json` の `robot.base_url`(運用値 `http://192.168.100.2:8000`、コード既定 `http://reachy-mini.local:8000`)。
- 動作は Mac 側で軌道を生成し、デーモンの WebSocket(`/ws/sdk` の `set_full_target`)へ 30 Hz(設定可)で流す。応答を待たないので Wi-Fi の往復遅延に縛られない。WebSocket が使えないときは HTTP の `set_target` に自動で落ちる。公式の感情モーション集(`moves/`、Apache-2.0)とパラメトリックなキーフレーム(`gestures.json`)を同じ仕組みで再生する。
- デーモン(v1.10.0)は HTTP keep-alive の接続再利用に応答しない癖があるため、HTTP は毎回新しい接続を張る(`Connection: close`)。名前解決(`reachy-mini.local`)は一度だけ行い IP をキャッシュする。
- 実機の頭部機構には 2〜3° の遊びがあり、指令に対して読み取り値は少し小さく出る(振幅 8° → 6° 程度)。ジェスチャーの見た目には影響しない。
- 顔追跡は 2 方式(`settings.json` の `motion.tracking.mode`)。
  - `app`(運用値。コード既定は `daemon`): デーモンの追跡は weight 0.01 の「顔検出器」としてだけ有効にし、顔の位置(鼻の x, y を −1〜1 に正規化した値)を 10 Hz で取得して、首と腰の目標を Mac 側(`app/tracker.py`)で作る。速度上限・不感帯・腰が追従し始める角度・見失ったときの保持と戻りを設定で調整できる。映像は Mac に送られず、保存もしない。
  - `daemon`: デーモン内蔵の追跡(首だけ・速さ固定・weight 1.0 だと外部からの頭部指令が無視される)。ジェスチャーの間だけ weight 0 にして戻す。
- ジェスチャーは「いま向いている方向」(gaze)に重ねて再生する。ランプアウトも gaze 基準のニュートラルへ戻すので、台詞のあとに子どもから顔をそむけない。`kind: point`(指さし)だけは絶対方向で再生する。首の相対角は 60° で打ち切る(デーモンの IK は 65° を超えると腰を勝手に回すため)。
- 公式モーション集に入っている腰(`body_yaw`)の回転もそのまま再生する。安全範囲(`motion.envelope`)には腰の上限も含む。
- 音声は録音(`recordings/`)または VOICEVOX のローカル合成。どちらもロボットへアップロードして本体スピーカーで鳴らし、`cache/` にキャッシュする。
- セッションの状態は変化のたびに `logs/.current_session.json` に保存し、サーバーが落ちても次回起動時に「続きから再開」できる(30 分以内)。停止時は `session.suspend()` で終了扱いにしない。
- 電池残量はロボットから読めないため、`app/power.py` が ssh で `/proc/uptime` と `vcgencmd get_throttled` を 15 秒ごとに読み、稼働時間と低電圧を UI と CSV に出す。
- 1 秒ごとにデーモンの状態を確認し、切断→復帰時はモーター有効化 → ニュートラル姿勢 → 音声の再アップロード → 追跡設定の再適用を自動で行う。

## トラブルシュート

| 症状 | 対処 |
|---|---|
| 「ロボット接続待ち」が続く | ロボットの電源・LAN ケーブルを確認。**USB LAN アダプタを別個体に替えた直後**は macOS 側の固定 IP が外れている(`sudo networksetup -setmanual "<アダプタ名>" 192.168.100.1 255.255.255.0`)。設定 > 一般 > ロボット URL が `http://192.168.100.2:8000` か確認 |
| 「VOICEVOX エンジンが見つかりません」 | `./setup_voicevox.sh` を実行。ログは `cache/voicevox.log` |
| ダッシュボード(Reachy Mini Control)のアプリが動いている | 先に停止する(ロボットの取り合いになる) |
| 音声と動作のタイミングがずれる | 設定 > 動作 > 音声先行(ms)を調整 |
| 頭が動かない(アンテナだけ動く) | `motion.tracking.mode = daemon` で weight 1.0 のときに頭部指令が無視される癖。運用値の `app` では起きない。操作画面の「ストップ」で復帰する |
| 録音の声が出ない台詞がある | その台詞の録音が無い(設定 > 声 に一覧)。`recordings/<声>/<ID>.m4a` を置けば次の準備で拾う |
| 設定が勝手に元に戻る | 古いコードのサーバーを動かしたまま設定を保存すると、そのサーバーが知らない新しい項目が消える。**コードを変えたら先に再起動する** |
| 動きがカクつく・遅れる | Wi-Fi 同士だと往復遅延が揺れる。Mac とロボットを有線 LAN にする。設定 > 動作 > 送信レートを下げるのも有効 |
| ロボットを休ませたあと | 操作画面の「起こす」を押すと無音でニュートラルに戻る |

```bash
cd experiment

```

## クレジット

- 音声合成: [VOICEVOX](https://voicevox.hiroshiba.jp/)。使用キャラクターのクレジット表記(例: `VOICEVOX:ずんだもん`)が必要。各キャラクターの利用規約に従うこと。
- モーション: Pollen Robotics [reachy-mini-emotions-library](https://huggingface.co/datasets/pollen-robotics/reachy-mini-emotions-library)(Apache-2.0)。詳細は `moves/CREDITS.md`。

## 将来の拡張

- `app/tts/base.py` の `TTSBackend` を実装すれば別の音声合成に差し替えられる。`tts.backend` は `Literal["voicevox"]` なので、**`app/config.py` の Literal と `app/main.py` の `make_tts()` にも新しい名前を足す**こと(知らない値を書くと settings.json が `.broken-<時刻>` に退避されて初期値に戻る)。録音した声からのゼロショット音声クローンもここに入る。
- 電池の持ち時間が CSV から分かったら、稼働時間に対する「残り目安」のしきい値を `settings.power` に追加する。
